## Why CheckMate?

Models, properties and information requirements are meant to assist planning and review — not put planners and reviewers in **"checkmate"**. CheckMate is designed as a partner in the review process: it brings requirements and IFC models together and makes results traceable.

The idea: **accelerate bureaucracy without lowering standards.** Clear, machine-readable requirements and digital tools help people focus on engineering judgment.

CheckMate originated at the [BIM Portal Hackathon 2025](https://www.bimdeutschland.de/veranstaltungen/hackathon-2025). This independent project processes requirements from the [German Federal BIM Portal](https://www.bimdeutschland.de/bim-portal) or from local IDS and `.rules.json` files.

<CardGrid>
  <Card title="Open exchange formats & BCF" icon="open-book">
    IFC describes the model, buildingSMART IDS the machine-readable requirements. Version 0.4 can also export findings directly as BCF 2.1 (`.bcfzip`).
  </Card>
  <Card title="3D browser workbench, CLI & MCP" icon="laptop">
    The 3D web workbench (`@checkmate/web`), command line (`@checkmate/cli`) and MCP server (`@checkmate/mcp`) share the same checking core (`@checkmate/core`) powered by IFClite.
  </Card>
  <Card title="Humans and AI with 3D MCP Apps" icon="approve-check-circle">
    An AI client can invoke checks over MCP, render interactive 3D views (`ui://checkmate/*`) and explain findings. Rules are evaluated deterministically in CheckMate; engineering decisions stay with humans.
  </Card>
  <Card title="Open and verifiable" icon="puzzle">
    CheckMate is open source under Apache 2.0. Both the Java edition (`0.3.2`) and the TypeScript/IFClite edition (`0.4`) run without proprietary libraries.
  </Card>
</CardGrid>

Not all IDS requirements or project rules can be verified automatically. [IFC and IDS](/CheckMate_BIMPortal/en/architecture/ifc-ids-checking/) explains the scope, property mapping and zero-applicability diagnosis; the [system architecture](/CheckMate_BIMPortal/en/architecture/overview/) describes packages and dependencies.
